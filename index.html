Everything you need to build an audio plugin for MOD-powered devices — from LV2 source to a working pedal, with its own web interface, on your unit.

Overview

Plugins for MOD are LV2 plugins — an open, extensible standard MOD did not invent and does not control. A plugin you write for MOD is a normal LV2 plugin that runs anywhere LV2 runs. There are no licensing requirements for making one: build it, install it, give it away, sell it elsewhere — none of that involves MOD.

MOD defines a small number of LV2 extensions that let a plugin describe itself more richly to MOD devices — how it looks, how it is categorised, how its controls behave. Using them is optional; a plugin with no MOD extensions at all still works.

ExtensionPurpose
mod:Plugin metadata — brand, label, ranges, per-device defaults, CV, file types
modgui:The plugin's web interface
modpedal:Pedalboard format — written by MOD's UI, not by plugin developers
mod:licenseCopy protection and trial mode, for commercial plugins

Under the hood

A MOD device runs an embedded Linux system with a real-time kernel. Audio is handled by JACK2, with mod-host on top loading and connecting plugins. mod-ui serves the web interface users actually see, and renders your modgui.

All MOD systems run at 48 kHz. The same stack runs on every MOD product, which is why one plugin bundle works across the range.

TargetArchitectureProduct
modduoARMv7 (Cortex-A7)MOD Duo
modduoxAArch64 (Cortex-A53)MOD Duo X
moddwarfAArch64 (Cortex-A35)MOD Dwarf
generic-x86_64x86-64Desktop — for building and validating
The Dwarf's Cortex-A35 is in-order and slower per clock than the Duo X's A53, so it is the target to size a CPU budget against. Most targets also have a -new variant (moddwarf-new and friends) on a newer toolchain — GCC 9.4.0, glibc 2.27 — which is what MOD's own builds use. generic-x86_64 is not a shipping device target. It exists so you can build and test on your own machine before cross-compiling, and it is the only target on which the automated runtime tests can run. Use it constantly — it will save you hours.

Darkglass Anagram

mod-plugin-builder also cross-compiles for the Darkglass Anagram — Darkglass's own hardware, on the same LV2 / JACK2 / mod-host stack. That's why darkglass-anagram platform names show up alongside MOD's own inside the toolchain. Darkglass maintain their own developer documentation for Anagram: Plugin-Dev-Setup. If you're building specifically for Anagram, start there.

Rust

Via the lv2 crate.

Pure Data

Via hvcc — no C++ required.

Via max-gen-skeleton.

Plain C

Direct against the LV2 headers — no framework required.
